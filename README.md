# 人物连续性记忆（SillyTavern）

这是一个为群像 AIRP 设计的 SillyTavern 扩展。它和 Anima 分工运行：

- Anima：事件记忆、向量/BM25 事件检索、知识库和状态变量。
- 本扩展：人物当前画像、成长里程碑、有向关系图谱及生成前召回。

## 仓库为什么同时包含前端和后端

同一个 GitHub 仓库可以安装两次：

1. 在酒馆“扩展 → 安装扩展”中粘贴仓库地址，安装前端。
2. 在 VPS 的 SillyTavern `plugins` 目录克隆同一仓库，加载后端。

前端通过 `/api/plugins/character-continuity` 调用后端。后端将数据保存在本仓库
运行副本的 `data/state.json`，每次整体导入或替换前会自动保留最近 20 份备份。
`data` 已加入 `.gitignore`，更新代码不会把私人记忆提交到 GitHub。

## 当前版本已经能做什么

- 从“人物记忆实验室”导出的 JSON 状态导入后端；
- 使用独立“人物档案库”保存画像、成长与关系，不再由世界书或单个聊天拥有；
- 同一角色卡下的多个聊天可以共享一个档案库，也可以分别绑定不同档案库；
- 聊天显式绑定优先于角色卡默认绑定，解绑单个聊天不会删除档案库；
- 支持克隆档案库，方便同一批人物开启不同世界观或平行线后各自发展；
- 从最近聊天识别出场人物；
- 按姓名精确读取当前画像；
- 从相关人物中检索少量成长里程碑；
- 先取本轮明确出现人物之间的直接关系；
- 一跳关系仅在相邻人物已有画像时补充，避免 Fi 这类中心节点把整张关系图拖进上下文；
- 在主回复生成前，以只读系统资料注入；
- 预览本轮实际召回内容；
- 从酒馆导出完整状态备份。
- 在酒馆扩展菜单中打开独立的全屏人物记忆工作台；
- 查看并人工编辑人物画像，必要时恢复模型生成版本；
- 查看成长里程碑时间线；
- 查看可拖拽的有向关系图，双向关系以两条曲线分别显示；
- 新增、编辑和停用人物关系，并保存节点位置；
- 在手机端使用抽屉导航和底部编辑窗口。
- 直接读取当前聊天的楼层，手动选择范围生成“画像 + 成长 + 有向关系”预览；
- 预览确认后才写入人物记忆，支持撤回已采纳批次；
- 支持 OpenAI 兼容接口（DeepSeek、GLM 等）和 Gemini 官方接口；
- 模型请求由后端异步执行，前端轮询结果，避免长任务被 Cloudflare 524 截断；
- 内置安全清洗：保留开场白和用户消息，角色回复自动剥离思考链、HTML/CSS、
  注释、状态栏标记并提取 `<content>` 正文；
- 每 N 楼自动分析和采纳已经实现，但默认关闭，可在质量稳定后再开启；
- 每个聊天窗口分别记录分析进度，不会把 A 窗口的楼层进度套到 B 窗口。

详细的 GitHub、VPS 和网页安装顺序见 [安装与发布.md](./安装与发布.md)。

## 本轮召回逻辑

1. 只读取当前聊天解析到的人物档案库；未绑定时不会分析、写入或注入。
2. 扫描最近若干条聊天，找出正文明确提到的人物，并补入当前角色卡人物。
3. 这些人物的当前画像按姓名精确读取，不做模糊猜人。
4. 成长里程碑使用“人物命中加权 + 文本词组重合”排序，取前 N 条。
5. 关系先取本轮人物之间的直接有向关系，再少量补入已有画像人物的一跳关系。
6. 所有内容受条数上限和总字符上限约束。
7. 前端在主回复生成前，把结果临时作为只读系统资料放到最后一条用户消息前。

生成前召回仍完全在 VPS 本机完成，不调用额外模型，也不产生 API 费用。只有在“人物更新”
中手动执行分析，或主动开启每 N 楼自动分析时，才会调用你配置的模型 API。

## VPS 安装

安装前先备份 SillyTavern 的 `config`、`data` 和 `plugins`。

前端在酒馆网页中安装。后端在你的部署结构中通常位于：

```text
/opt/sillytavern/docker/plugins/character-continuity
```

把本仓库克隆到该目录，然后重启 SillyTavern 容器。服务器必须已经设置：

```yaml
enableServerPlugins: true
```

重启后从酒馆扩展菜单打开“人物连续性记忆”，在“设置与备份”中点击“检查后端”。
显示版本和批次数即代表连接成功。

## 档案库与聊天如何绑定

档案库是独立的数据容器，不属于世界书，也不会因为删除或解绑聊天而消失。

1. 首次使用时，在工作台顶部新建档案库，并绑定当前聊天。
2. 同一角色卡的其他聊天可把该库设为“角色卡默认”，自动继承同一套人物资料。
3. 某个聊天需要独立世界线时，克隆当前库，再把该聊天显式绑定到克隆库。
4. 聊天显式绑定始终优先于角色卡默认；取消显式绑定后会回退到角色卡默认。
5. 若同时取消聊天绑定和角色卡默认，该聊天进入“未绑定”状态，不会误写或误注入。

从 0.3.x 升级时，旧的“故事 + 时间线”资料会自动迁移为独立档案库。迁移不会
删除旧画像、关系或历史批次；第一次产生写操作时，新结构会随状态备份一起落盘。

## GitHub 发布

在 GitHub 新建一个空的公开或私有仓库，不要勾选自动创建 README。随后在本目录
初始化 Git，提交文件并推送。推送前务必确认 `data/state.json` 没有进入暂存区。

建议仓库名：

```text
ST-Character-Continuity
```

公开发布前需要补全许可证文件、截图、隐私说明和版本发布记录。

## 安全说明

SillyTavern 服务端插件不受沙箱保护。本插件只读写自己的 `data` 目录，不接收任意
文件路径。人物分析开启时，选定楼层的清洗后正文会发送给你明确配置的模型 API；
召回和浏览资料不会对外发送内容。API Key 保存在后端 `data/analysis-config.json`，
不会随状态导出返回前端，也被 `.gitignore` 排除。人物记忆可能包含私密剧情，仓库更新
和问题反馈时不要上传 `data` 目录、日志或导出的状态备份。
