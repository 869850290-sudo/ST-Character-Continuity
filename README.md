# 人物连续性记忆（SillyTavern）

这是一个为群像 AIRP 设计的 SillyTavern 扩展。它和 Anima 分工运行：

- Anima：事件记忆、向量/BM25 事件检索、知识库和状态变量。
- 本扩展：人物当前画像、成长里程碑、有向关系图谱及生成前召回。

## 仓库为什么同时包含前端和后端

同一个 GitHub 仓库可以安装两次：

1. 在酒馆“扩展 → 安装扩展”中粘贴仓库地址，安装前端。
2. 在 VPS 的 SillyTavern `plugins` 目录克隆同一仓库，加载后端。

前端通过 `/api/plugins/character-continuity` 调用后端。后端将数据保存在本仓库
运行副本的 `data/state.json`，每次整体导入或替换前会自动保留最近 20 份备份。
`data` 已加入 `.gitignore`，更新代码不会把私人记忆提交到 GitHub。

## 当前版本已经能做什么

- 从“人物记忆实验室”导出的 JSON 状态导入后端；
- 按故事和时间线隔离数据；
- 从最近聊天识别出场人物；
- 按姓名精确读取当前画像；
- 从相关人物中检索少量成长里程碑；
- 先取本轮明确出现人物之间的直接关系；
- 一跳关系仅在相邻人物已有画像时补充，避免 Fi 这类中心节点把整张关系图拖进上下文；
- 在主回复生成前，以只读系统资料注入；
- 预览本轮实际召回内容；
- 从酒馆导出完整状态备份。
- 在酒馆扩展菜单中打开独立的全屏人物记忆工作台；
- 查看并人工编辑人物画像，必要时恢复模型生成版本；
- 查看成长里程碑时间线；
- 查看可拖拽的有向关系图，双向关系以两条曲线分别显示；
- 新增、编辑和停用人物关系，并保存节点位置；
- 在手机端使用抽屉导航和底部编辑窗口。

详细的 GitHub、VPS 和网页安装顺序见 [安装与发布.md](./安装与发布.md)。

## 本轮召回逻辑

1. 只读取设置中指定的“故事 + 时间线”，不会跨剧本串数据。
2. 扫描最近若干条聊天，找出正文明确提到的人物，并补入当前角色卡人物。
3. 这些人物的当前画像按姓名精确读取，不做模糊猜人。
4. 成长里程碑使用“人物命中加权 + 文本词组重合”排序，取前 N 条。
5. 关系先取本轮人物之间的直接有向关系，再少量补入已有画像人物的一跳关系。
6. 所有内容受条数上限和总字符上限约束。
7. 前端在主回复生成前，把结果临时作为只读系统资料放到最后一条用户消息前。

当前检索完全在 VPS 本机完成，不调用额外模型，也不产生 API 费用。

## VPS 安装

安装前先备份 SillyTavern 的 `config`、`data` 和 `plugins`。

前端在酒馆网页中安装。后端在你的部署结构中通常位于：

```text
/opt/sillytavern/docker/plugins/character-continuity
```

把本仓库克隆到该目录，然后重启 SillyTavern 容器。服务器必须已经设置：

```yaml
enableServerPlugins: true
```

重启后从酒馆扩展菜单打开“人物连续性记忆”，在“设置与备份”中点击“检查后端”。
显示版本和批次数即代表连接成功。

## GitHub 发布

在 GitHub 新建一个空的公开或私有仓库，不要勾选自动创建 README。随后在本目录
初始化 Git，提交文件并推送。推送前务必确认 `data/state.json` 没有进入暂存区。

建议仓库名：

```text
ST-Character-Continuity
```

公开发布前需要补全许可证文件、截图、隐私说明和版本发布记录。

## 安全说明

SillyTavern 服务端插件不受沙箱保护。本插件只读写自己的 `data` 目录，不接收任意
文件路径，也不会将状态上传到外部服务。人物记忆可能包含私密剧情，仓库更新和问题
反馈时不要上传 `data` 目录或导出的状态备份。
